\chapter{Resultados e Testes}
\label{chap:resultados}

Neste capítulo, são apresentados os resultados práticos da compilação de três algoritmos clássicos implementados na linguagem C-: o algoritmo de Euclides para o cálculo do Máximo Divisor Comum (MDC), o algoritmo de Fatorial Recursivo e o algoritmo de ordenação Selection Sort. O objetivo é demonstrar a correção do fluxo completo de compilação, desde a validação léxica, sintática e semântica, passando pela geração do código intermediário em quádruplas, sua tradução em instruções Assembly e, finalmente, a execução do código binário de 32 bits correspondente.

Para cada algoritmo, é apresentada uma tabela comparativa unificada contendo o código fonte original alinhado com suas quádruplas intermediárias, instruções Assembly nativas com seus respectivos endereços (PC) e a codificação de máquina equivalente.

\section{Algoritmo de Euclides: Máximo Divisor Comum (MDC)}
\label{sec:res_gcd}

O primeiro caso de teste é o algoritmo de Euclides, que calcula o MDC de forma recursiva. Este caso valida o correto funcionamento de condicionais, operações aritméticas e o suporte a chamadas de função recursivas simples com passagem de múltiplos parâmetros em registradores.

No projeto de hardware, a convenção de chamadas utiliza os registradores temporários para operações e realiza o salvamento local na pilha. A correspondência detalhada de instruções é apresentada na Tabela \ref{tab:gcd_res}.

\subsection{Análise Comparativa}
Como pode ser observado na Tabela \ref{tab:gcd_res}, a transição das quádruplas intermediárias para as instruções Assembly demonstra a eliminação de metadados como marcas de escopo (\texttt{FUN}, \texttt{END}) e argumentos formais (\texttt{ARG}), os quais são resolvidos internamente pelo compilador na atribuição de endereços estáticos de RAM. As operações aritméticas simples mantêm uma correspondência 1:1, enquanto operações de controle como chamadas de função (\texttt{CALL}) e retornos (\texttt{RET}) se expandem para instruções de salvamento de pilha e manipulação do registrador de retorno (\texttt{\$ra}), preservando o fluxo de execução recursivo. Por fim, cada instrução Assembly ativa gera exatamente uma palavra de máquina de 32 bits, resultando em uma correspondência estrita de 1:1 entre a listagem Assembly final e o código executável.

\section{Algoritmo de Fatorial Recursivo}
\label{sec:res_fact}

O algoritmo de Fatorial Recursivo testa o empilhamento e desempilhamento sucessivo de múltiplos frames de ativação no ambiente de execução. Este teste exige que o compilador preserve o endereço de retorno (\texttt{\$ra}) e o parâmetro local (\texttt{n}) a cada nova autoinvocação na pilha, realizando o desempilhamento correto (unwinding) e a correta propagação do resultado aritmético acumulado via registrador temporário.

A Tabela \ref{tab:fact_res} apresenta a correspondência detalhada dos códigos para este algoritmo.

\subsection{Análise Comparativa}
Na execução do Fatorial Recursivo, nota-se o uso intensivo de instruções de controle de pilha (\texttt{STORE\_STACK} e \texttt{LOAD\_STACK}). Quando a função \texttt{fact} é chamada de forma recursiva, as instruções geradas salvam o valor de \texttt{n} e o registrador \texttt{\$ra} na pilha. Ao retornar da chamada recursiva, esses valores são restaurados para que a multiplicação local pelo registrador temporário possa ocorrer de forma isolada, sem que as autoinvocações subsequentes corrompam os valores do nível de recursão anterior. O mapeamento do Assembly para o Binário é direto (1:1), traduzindo mnemônicos como \texttt{BGT}, \texttt{MULT} e \texttt{JR} diretamente para suas respectivas codificações de máquina.

\section{Algoritmo de Ordenação: Selection Sort}
\label{sec:res_sort}

O algoritmo Selection Sort (Ordenação por Seleção) é utilizado para validar a robustez do compilador frente a estruturas de dados compostas (vetores), passagem de parâmetros por referência (ponteiros de vetores) e loops aninhados com chamadas de sub-rotinas intermediárias.

Este algoritmo faz uso do vetor global estático \texttt{vet} com 10 elementos e implementa a passagem por referência da base do vetor para a função \texttt{minloc} e para a sub-rotina \texttt{sort}. A correspondência detalhada de instruções é apresentada na Tabela \ref{tab:sort_res}.

\subsection{Análise Comparativa}
O Selection Sort evidencia uma characteristic singular na geração do código binário executável: a expansão de instruções individuais do Assembly em sequências de instruções de máquina de 32 bits. Isso ocorre para otimizar o cálculo de índices de vetores na ausência de múltiplos registradores de base de hardware ou operações aritméticas de deslocamento (shift) complexas na ULA. 

Por exemplo, a instrução Assembly \texttt{LOAD \$t1, a, \$t0} (carregamento de um elemento de vetor parâmetro por referência) expande-se em 3 palavras de instrução binária:
\begin{enumerate}
    \item \texttt{ADDI \$t1, \$zero, 40} - carrega o endereço base do vetor parâmetro \texttt{a} (que é 40).
    \item \texttt{ADD \$t1, \$t1, \$t0} - soma a base do vetor ao deslocamento do índice acumulado em \texttt{\$t0}.
    \item \texttt{LOAD \$t1, 0(\$t1)} - realiza o carregamento real do valor do elemento na memória RAM para o registrador alvo.
\end{enumerate}

Essa expansão controlada no backend do compilador permite que o processador simplificado execute acessos indexados a arrays sem sobrecarregar a ULA com unidades de multiplicação ou de deslocamento (shift) complexas de hardware.
